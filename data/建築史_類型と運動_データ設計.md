# 建築史：類型・様式・運動データ設計

## 分類原則

| kind | 判断基準 | 例 |
|---|---|---|
| `building-type` | 用途、利用者、空間構成の系譜 | 集合住宅、寺院、劇場 |
| `style` | 時代・地域に共有された構成・意匠 | ゴシック、書院造、帝冠様式 |
| `movement` | 主張と担い手を伴う集団的活動 | 工芸美術運動、メタボリズム |
| `theory` | 設計・都市・保存を導く概念 | 近代建築五原則、近隣住区 |
| `institution` | 保存・指定・評価の制度や憲章 | 登録有形文化財、ヴェネツィア憲章 |

「様式・運動・制度について説明せよ」という出題形式は一緒でも、データ上では混同しない。画面では必要に応じて「運動・様式・思想」に束ねて表示する。

## ID と関係

- ID は英小文字 kebab-case。名称変更後も変更しない。
- `parentId` は類型の階層に使う。
- `relatedTopicIds` は影響、併存、対立などの弱い関係。
- `evolution.previous/next` は明確な前後関係だけに使う。
- `representativeBuildingIds` は将来、建築カードを表示名ではなく安定 ID に移行して接続する。
- `examEvidence` は出題年・区分・問題番号・元ファイルを保持し、頻度を手入力しない。

## 图片原则

图片只作为记忆辅助素材，不区分外观、平面、剖面或考试原图。每栋建筑关联一个或多个图片文件即可；保留来源定位，但不增加图片类别字段。

## 完成度

- `core`: 過去問に直接出た、または解答に不可欠。
- `extended`: 系譜理解のために補う項目。
- 現段階の一覧は対象範囲を確定する「マスター清单」。詳説は空欄を許容し、段階的に追加する。
