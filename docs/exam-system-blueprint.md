# 建筑考试学习系统：两日收口蓝图

> 目标：在考试前约 40 天，把现有网页从“许多资料视图”收口成一个清晰、稳定、仍然有探索趣味的学习中心。

## 1. 产品定义

本系统不是 Notion 的替代品，也不是 Anki 的替代品。

- **Notion**：教材拆解后形成的原始、详细知识数据库，是知识内容的源头。
- **网页**：以过去问为起点，重新组织知识、题目和学习行为的中心。
- **Anki**：对需要长期保持的最小知识单元进行辅助记忆。

网页的核心任务是形成闭环：

```text
过去问 / 模拟题
  → 作答
  → 查看并判断答案
  → 标记错误或不确定
  → 回到网页知识节点或 Notion 原始资料
  → 再次作答
  → 必要时进入 Anki
```

## 2. 收口原则

1. **不大规模迁移 Notion**：网页只保存考试导航所需的摘要、关联和状态；详细教材笔记仍以 Notion 为准。
2. **不删除已有探索成果**：时间轴、网络、地图、卡片继续存在，但不再全部平铺在主导航。
3. **题目是主索引**：年份、科目、考点、答案和学习记录最终都要能回到题目。
4. **答案必须显示可靠性**：有文字不等于已确认。
5. **两天内先完成可用主干**：之后允许根据真实学习体验继续演化，但不让低价值开发挤占备考。
6. **趣味性来自自由探索与知识连接**，不在此阶段开发积分商城、复杂等级或大型动画。

## 3. 顶层信息架构

```text
首页 /
├─ 探索 /explore
│  ├─ 学科知识地图
│  ├─ 建筑史时间轴
│  ├─ 建筑史卡片
│  ├─ 建筑史关系网络
│  ├─ 西洋核心建筑
│  ├─ 建筑史 × 构法
│  └─ 随机探索（第二优先级）
│
├─ 试题库 /exam
│  ├─ 过去问 /exam/past
│  ├─ 题目详情 /question/[id]
│  └─ 模拟题 /exam/mock（先放愿景入口，不在两日内完成生成系统）
│
└─ 练习 /practice
   ├─ 各科知识地图中的拆分练习
   ├─ 错题
   ├─ 不确定
   ├─ 稍后再做
   ├─ 待复核答案
   └─ 知识缺口 / Anki 建议
```

### 顶级导航

桌面端和移动端都只保留五个顶级入口：

1. 首页
2. 探索
3. 试题库
4. 练习
5. Notion 原始知识库（外链）

时间轴、关系网络和建筑卡移动到“探索”；完整题目筛选进入“试题库”；各科知识地图进入“练习”。

## 4. 首页蓝图

首页不再直接等于题目列表。题目列表移动到 `/exam/past`。

```text
┌─────────────────────────────────────────────────────────┐
│ 距离考试 4x 天                         继续上次学习 →    │
│ 今天只需要选择一种进入方式                              │
├─────────────────┬─────────────────┬─────────────────────┤
│ 🧭 探索          │ 📚 试题库         │ ✍️ 练习              │
│ 从兴趣和联系进入 │ 过去问/模拟题    │ 分类拆分题与回流队列 │
│ 随机探索 →       │ 开始一组 →       │ 今日队列 →           │
├─────────────────────────────────────────────────────────┤
│ 今日概况                                                │
│ 未做题目 · 错题 · 不确定 · 待复核答案                   │
├─────────────────────────────────────────────────────────┤
│ 最近的知识路径 / 最近补上的内容（可选，第二天再做）      │
└─────────────────────────────────────────────────────────┘
```

### 首页第一版必须有

- 三个模式卡片。
- 过去问题目总数。
- 本地保存的错题、不确定和稍后再做数量。
- “继续上次题目”。
- Notion 总入口。

### 首页第一版不做

- 虚构的掌握率。
- 复杂统计图。
- 成就、积分或连续学习天数。
- AI 今日计划。

## 5. 三种模式的职责

### 5.1 探索模式

回答：“我想理解什么，或者今天想从哪里逛进去？”

探索首页按**问题**而不是按组件名称组织：

| 我想做什么 | 进入现有页面 |
|---|---|
| 看建筑如何随时间变化 | `/timeline` |
| 看样式、运动、建筑师和建筑的关系 | `/history/network` |
| 系统学习建筑史卡片 | `/history` |
| 用图片和空间/构造认识建筑 | `/architecture-cards` |
| 集中看西洋核心建筑 | `/history/western-core` |
| 从构法理解建筑史 | `/history-construction` |
| 查看建筑史整体考点 | `/architecture-history-knowledge-map` |
| 查看建筑计划考点 | `/planning-knowledge-map` |
| 查看建筑计划平面类型 | `/planning-typology` |
| 查看环境工学考点 | `/environment-knowledge-map` |
| 快速复习环境公式 | `/environment-knowledge` |
| 查看建筑构法考点 | `/construction-methods-knowledge-map` |
| 查看结构力学考点 | `/knowledge-map` |

每张入口卡必须有一句“适合什么时候用”，避免用户需要先理解页面名称。

探索页面的统一出口：

- 查看相关过去问。
- 返回探索首页。
- 打开对应 Notion 原始资料（存在时）。

第二优先级趣味功能：随机建筑、随机知识节点、“沿这条关系继续探索”。若两日时间不足，不阻塞收口。

### 5.2 试题库

回答：“考试会怎么问，我现在能不能答？”

第一版由现有首页题目筛选器迁移而来：

- 过去问入口。
- 年份、试验区分、科目、标签筛选。
- 全部 / 未做 / 错题 / 不确定 / 稍后再做。
- 题目卡显示答案状态。

题目详情第一版学习操作：

```text
[未做] [答对] [答错] [不确定] [稍后再做]
```

本地学习记录最小结构：

```ts
type StudyStatus = "unseen" | "correct" | "wrong" | "uncertain" | "later";

interface QuestionStudyRecord {
  questionId: string;
  status: StudyStatus;
  attempts: number;
  updatedAt: string;
}
```

第一版使用 `localStorage`，不引入账户和后端。题目 ID 必须采用稳定文件名或稳定 ID，不继续依赖数组下标；否则题目排序变化会让学习记录错位。

答案可靠性统一为：

| 状态 | 含义 | UI |
|---|---|---|
| `missing` | 尚无答案 | 灰色 |
| `ai-draft` | AI 生成，未对照资料 | 黄色 |
| `source-supported` | 已有卡片/资料支持 | 蓝色 |
| `reviewed` | 已人工检查 | 绿色 |
| `questionable` | 存在疑问 | 红色 |

现有 `planning-exam-answers.json`、`construction-exam-answers.json` 等状态在读取层映射到以上五类，不立即批量改写全部数据。

#### 模拟题

两日版本只建立入口说明和数据契约，不建设自动生成界面。

```ts
interface MockQuestionProvenance {
  sourceQuestionIds: string[];
  sourceKnowledgeIds: string[];
  generationPattern: "variant" | "reframed" | "combined";
  generatedBy: "ai" | "human";
  reviewStatus: "ai-draft" | "reviewed" | "questionable";
}
```

模拟题必须能说明：模仿了什么过去问、用了什么数据库知识、改变了什么条件。

### 5.3 练习

回答：“我想按什么知识类别练习，以及根据已经做过的事情应该补什么？”

第一版以各科知识地图作为分类练习入口，并汇总真实状态：

1. 错题。
2. 不确定题。
3. 稍后再做。
4. 待复核答案。
5. 尚无答案的题目。

排序规则：

```text
错题 > 不确定 > 稍后再做 > 待复核答案 > 尚无答案
```

复习动作：

- 再做一次。
- 查看答案与依据。
- 打开相关知识地图。
- 打开 Notion 原始笔记。
- 标记“需要 Anki”（第二优先级；第一版可只做本地标签）。

## 7. 数据权威与关联规则

| 数据 | 权威来源 | 网页保存什么 |
|---|---|---|
| 教材拆解、详细解释 | Notion | 摘要、Notion URL、知识 ID |
| 过去问原文、年份、题号、图片 | `processed_questions` / 原卷资料 | 完整题目与稳定 ID |
| AI/人工答案 | 专科答案 JSON + 题目 Markdown | 答案、依据、可靠性状态 |
| 建筑实体和关系 | 网页结构化数据 | 实体、别名、图片、题目证据 |
| 日常记忆 | Anki | 是否已有卡、Anki 标识或标签 |
| 当前学习状态 | 网页本地存储 | 作答状态、次数、最近时间 |

### 禁止的重复

- 不把 Notion 长文整篇复制到网页。
- 不在网页重新实现 Anki 间隔重复。
- 不让模拟题失去来源说明。
- 不同时维护两个题目主清单。

## 8. 当前必须先解决的技术问题

### P0：两日内必须

1. **可见乱码**：全局导航、首页、metadata、部分历史网络关系文本、注释和标签已有明显乱码。先修用户能看到的文字；内部注释可延后。
2. **题目主数据统一**：`data/questions.json` 当前无法可靠解析；确认 `processed_questions` 为主来源，旧 JSON 冻结或移出运行链路。
3. **稳定题目 ID**：`/question/[id]` 当前使用数组下标，必须改为稳定 ID 才能安全保存学习记录。
4. **模式导航**：把现有平级长导航收成首页、探索、试题库、练习和 Notion。
5. **本地学习状态**：至少支持答对、答错、不确定、稍后再做。
6. **基本构建验证**：完成后通过 lint/build；重点验证中文文件名和动态路由。

### P1：有余力再做

1. 探索页面统一“相关过去问”出口。
2. 答案状态统计。
3. 继续上次题目。
4. 随机探索。
5. 需要 Anki 标记。

### 明确不在两日内做

- 模拟题自动生成后台。
- AI 自动评分。
- 用户账户、数据库和云同步。
- 精细掌握度算法。
- 全量 Notion 同步。
- 复杂游戏化系统。
- 重写所有现有知识地图。

## 9. 两日实施顺序

### 第一天：结构收口与可用性

#### 上午：底座

1. 确认 `getAllQuestions()` 的真实主数据来源。
2. 定义稳定题目 ID。
3. 定义学习记录和答案状态的读取接口。
4. 修复全局可见乱码与 metadata。

#### 下午：入口

5. 新建模式首页 `/`。
6. 将当前题目列表迁移到 `/exam/past`（或先用 `/exam`）。
7. 新建 `/explore`，只做现有页面目录卡片，不重写子页面。
8. 重组全局导航。

#### 晚上：考试动作

9. 在题目详情增加五种学习状态。
10. 使用稳定 ID 写入 `localStorage`。
11. 增加上一题、下一题和返回题库。

### 第二天：练习闭环与收尾

#### 上午：练习页

1. 新建 `/practice`，集中各科知识地图与回流队列。
2. 汇总错题、不确定和稍后再做。
3. 汇总待复核/缺失答案（若读取成本低）。
4. 支持直接进入再次作答。

#### 下午：关联与趣味

5. 在探索目录写清每个视图的用途。
6. 为关键知识地图增加返回题库入口。
7. 有余力时加入随机建筑/随机探索；没时间则跳过。

#### 晚上：验收

8. lint、build、关键页面手动检查。
9. 检查刷新后学习状态是否仍存在。
10. 检查题目排序变化是否不会错配状态。
11. 记录未做事项；后续由真实学习反馈决定是否继续调整。

## 10. 两日结束的验收标准

只有以下条件全部满足，才算“系统已经弄干净”：

- [ ] 打开首页十秒内能理解探索、试题库、练习的区别。
- [ ] 主导航不再平铺十几个知识页面。
- [ ] 能按年份、科目和标签找到过去问。
- [ ] 题目详情能标记答对、答错、不确定或稍后再做。
- [ ] 刷新网页后状态仍然存在。
- [ ] 练习页能进入各科知识地图，并列出错题、不确定和稍后再做。
- [ ] 每个探索入口说明它适合解决什么问题。
- [ ] 能从探索回到题目，从题目回到相关知识（至少关键科目可用）。
- [ ] 用户可见的核心导航和首页没有乱码。
- [ ] 题目学习状态不依赖数组下标。
- [ ] 项目能够构建。
- [ ] 模拟题愿景有位置和数据契约，但没有阻塞当前学习。

## 11. 两日后的使用节奏

系统收口后，开发不再是每天的默认活动，但架构可以继续随使用体验演化。

建议每次学习：

```text
5–15 分钟探索（可选，用于启动兴趣）
→ 45–90 分钟过去问
→ 20–40 分钟订正与补知识
→ 10–20 分钟复习队列 / Anki
```

之后只允许三类修改：

1. 修复阻碍学习的错误。
2. 补充真实题目、答案和来源。
3. 根据实际做题暴露出的需求做小改动。

其余想法统一进入考试后的愿景清单。

## 12. 考试后的延伸愿景

考试模式最终扩展为：

```text
真实过去问模式库
  + Notion 原始知识数据库
  + 网页结构化知识与案例
  → 有来源的模拟题
  → AI 辅助答案与评分
  → 错误归因到知识节点
  → 个性化再次练习
```

模拟题的价值不在数量，而在保留真实过去问的出题结构，并能追溯到你的知识数据库。
